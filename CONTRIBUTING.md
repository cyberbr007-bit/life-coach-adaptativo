# Contribuições

Descreva o problema, comportamento esperado, evidência de reprodução e escopo da mudança. Use exemplos sintéticos; não anexe conversas ou dados reais.

Para desenvolvimento:

```bash
npm ci
npm run verify
```

Preserve os testes de aceitação e o padrão de verificação durante correções. Uma mudança de requisitos deve ser explícita e separada da tentativa de corrigir um defeito. Registre causa, correção, evidência e reversão em learnings.md quando houver um incidente concreto.

Contribuições para autonomia, autenticação, permissões, memória e exclusão precisam explicar o impacto sobre dados existentes e demonstrar os limites do comportamento. Não adicionar coleta de dados, telemetria externa ou integrações pagas silenciosamente.

Mantenha a distinção entre relato, observação e inferência. Recorrência gera candidatura; aprovação de uma estratégia exige um processo de avaliação que ainda está em desenvolvimento.
